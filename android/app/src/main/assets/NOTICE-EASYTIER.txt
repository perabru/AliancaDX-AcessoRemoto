The application dynamically links libeasytier_android_jni.so (the included C JNI
adapter) with libeasytier_ffi.so (EasyTier 2.6.4), compiled from source for Android.
It does not reuse the desktop Windows binaries or the Tauri GUI APK library.
The configured transport uses no_tun=true and loopback-only TCP forwarding.
The application does not establish a system VPN or request a TUN descriptor.
The EasyTier Cargo tun feature is compiled because upstream Android launcher
code requires its types; the runtime no_tun setting remains enabled.

BUILD CHANGES
No Rust application source behavior was changed. prepare_native_source.py:
- selects a reduced Cargo workspace containing EasyTier, rpc-build and FFI;
- selects EasyTier smoltcp, socks5, websocket, aes-gcm, tun and magic-dns features;
- replaces locked registry/git dependencies with the supplied exact local sources;
- removes the host-only mold linker choice, which is unavailable in this builder.
The JNI adapter is included as source in easytier_jni.c. It serializes native
operations and exposes sanitized errors so TOML source excerpts cannot leak
pairing secrets. Read JNI_README.md for the Kotlin API and readiness semantics.

CORRESPONDING SOURCE
The two accompanying archives contain the exact upstream EasyTier 2.6.4 source
and complete expanded registry/git dependency snapshots. source-inventory.json
preserves upstream hashes and source-tree verification. The source closure is
conservative and includes optional, target and development packages that are not
all linked into the Android libraries. The upstream source package excludes
proprietary precompiled third-party Windows driver DLL/SYS artifacts; those are
irrelevant to this Android build. The JNI wrapper, preparation script and native
build script are provided alongside the complete Kotlin application source.

See BUILD_ANDROID.md and build_android.sh. Rust 1.95.0, Android NDK r27c,
Protobuf/protoc 30.2, and Python 3.12+ are external build prerequisites. Toolchain
binaries are not included. Build fingerprints and ELF validation are recorded in
NATIVE_PROVENANCE.json. Device, public-relay and Windows/WAN tests are separate
from native compilation and must not be inferred from these build results.
