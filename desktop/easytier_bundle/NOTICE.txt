MiniAnyDesk starts the unmodified official easytier-core.exe as a separate child
process using local configuration. The Python application
is not linked to the Rust library. No VPN account, packet-capture driver, service,
virtual network adapter, or WinPcap/Npcap installer is part of this bundle.
The networking mode is userspace/no-TUN, with a local TCP port forward.
The unused management helper easytier-cli.exe is not distributed or required.
Host readiness is checked through the application's TLS connection.

RUNTIME PACKAGING CHANGE
The upstream Windows ZIP contains a proprietary Npcap 1.79 Packet.dll. That DLL
is NOT redistributed here. Packet.dll is instead the unmodified, BSD-licensed
AMD64 Vista variant from the official WinPcap 4.1.3 installer (file version
4.1.0.2980). It is present only because the EasyTier PE import table requires
11 WinPcap-compatible API symbols at load time, not through delay loading.
The DLL is therefore required even when the transport is configured no-TUN.
No capture-driver installer is included or invoked by MiniAnyDesk.
Static review confirms the required exports/ordinals and system-DLL imports.
This review is not an execution test on Windows and does not establish that no
Packet API is called at runtime.

SOURCES AND MODIFICATION
The accompanying easytier-2.6.4-source.tar.gz contains upstream Rust code,
Cargo.lock, build scripts and workspace metadata. Precompiled third-party
DLL/SYS/LIB payloads under easytier/third_party were omitted; x86_64/i686
Packet.lib import libraries were replaced with the BSD-licensed official
WinPcap 4.1.2 SDK libraries. See MINIANYDESK_SOURCE_CHANGES.txt inside the archive.
Rust application code and Cargo.lock are unchanged. This is a source packaging
change; the shipped EasyTier core EXE remains a byte-for-byte upstream artifact.
The original WinPcap 4.1.3 source archive is also included.

The easytier-2.6.4-dependency-sources.tar.xz archive contains the complete
EXPANDED contents of the exact registry .crate source archives and locked Git
snapshots, grouped under per-package namespaces. No source member was omitted.
Original registry artifact SHA-256 values remain verified against Cargo.lock;
Git source commits remain pinned. Each expanded package was read back from the
finished XZ archive and compared against every original member using a semantic
SHA-256 tree digest covering path, file type, permission mode, size, link target and file bytes.
source-inventory.json records original artifact hashes, expanded paths, tree
hashes, member counts and the final XZ archive hash. Its conservative closure
includes all target, optional, build and development dependencies of easytier/
easytier-rpc-build; some are not linked into these executables. Both local
workspace packages are contained in the separate EasyTier source archive.
The exact dependency contents were recompressed together to avoid the size cost
of hundreds of independently compressed source archives. The helper
installer/repack_easytier_sources.py reproduces and verifies this transformation.
No separate toolchain executable is supplied; the system compiler/SDK remains a
build prerequisite. Rust standard toolchain licenses are in the third-party file.

You may inspect, modify, rebuild and replace EasyTier under its license. For a
modified compatible runtime, rebuild locally and regenerate the distribution's
integrity manifest using the included
Python packaging sources. No secret signing key is required by this package.
The default integrity check detects unexpected binary changes; it does not
remove the license rights to inspect or modify the accompanying sources.
See installer/REBUILD.txt in the MiniAnyDesk source package for build details.
Use Rust 1.95/MSVC x64, Protobuf/protoc, the pinned Cargo.lock and upstream
.cargo/config.toml. The upstream Windows release enables mimalloc:
  cargo build --locked --release --target x86_64-pc-windows-msvc -p easytier --features mimalloc --bin easytier-core --bin easytier-cli
Extract the dependency tar.xz archive to inspect/modify the complete locked
sources under locked-sources/registry and locked-sources/git. Cargo can fetch
the same pinned public sources, or an equivalent local vendor directory can
be prepared from these supplied source trees. Rebuilt EXEs need not be byte
identical because compiler/build metadata can differ.
